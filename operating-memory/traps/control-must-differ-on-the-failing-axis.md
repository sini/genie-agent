---
name: control-must-differ-on-the-failing-axis
description: Applies when you re-run a measurement "another way" to confirm it.
type: trap
verified: unverified
---

**Rule:** A confirming arm must differ from the first in the step that could be broken, not merely in
the tool. If both arms share the suspect step, their agreement is no evidence.

**Why:** Measured cases:

- A phrase search was re-run with `grep -F` instead of `tr -s` + `grep`. Both read 0, which looked like
  corroboration, but both ran over the same broken flatten.
- An agent checked "the formatter is not exposed by these flakes" by grepping the ROOT `flake.nix` in
  two repos; the two zeros agreed and were read as a control. The output was generated by a framework
  (grep cannot see it) and lived in a different flake. A control broken in the same direction as the
  claim agrees with the claim.
- A probe overriding a flake input ran "pinned" and "overridden" arms that matched byte for byte. The
  override was silently inert, so both arms measured the same tree.
- A live control can also be WRONG the other way: a control demanding a refusal where a correct build
  makes refusal impossible reds against a correct build. Check that a control passes at GREEN before
  trusting it.

**How to apply:**

- Name the step most likely to be wrong; make the second arm bypass that step.
- Two arms agreeing byte for byte is a signal to check that the variable actually changed.
