---
name: claude-code-hook-delivery
description: When a Claude Code hook is supposed to inject context or messages into the model
type: trap
---

**Rule:** Verify that a hook's output reaches the model, on the event you wire it to, before trusting it. Firing is not delivery.

**Why / measured (one CLI version; re-probe on upgrade):** `SubagentStop` hooks fired reliably, as their own log file proved, yet their stdout reached the model on no output shape. Ten firings emitting both `systemMessage` and `hookSpecificOutput.additionalContext` produced zero deliveries. The same `additionalContext` shape delivered on `PreToolUse`, and `SessionStart` delivered seven times in the same transcript. It is not a schema problem; that event has no delivery path. A hook can be correct, fire every time, and speak to nobody for the life of the wiring.

**How to apply:**

- Measure on the transcript's attachment channel: select entries with `type == "attachment"`, then grep for the sentinel. A raw grep finds your own sentinel, because you wrote it in the tool call that installed the probe, and the control burns the same way.
- Use a sentinel that you did not author into the transcript (for example, one generated by the hook at run time).
- Hook wiring that is chained into shared hook files can be overwritten. Re-check it after tool installs.
